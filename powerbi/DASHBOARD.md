# Power BI desktop report: build instructions

This repository supplies Power Query M and DAX assets for a **native Power BI Desktop report**. It does not provide a fabricated PBIX/PBIT binary: Power BI Desktop is not installed in the Linux preparation environment, and an authentic dashboard depends on the real monthly cohort.

## 1. Connect to PostgreSQL

1. Start and load the database: `make db-up`, then `make load`.
2. In Power BI Desktop (Windows), select **Get data → PostgreSQL database**.
3. Server: `localhost:5432` (adjust if `.env` uses a different host/port). Database: `survival_abc` (or your configured database).
4. Select **Import** mode for a portable/report-responsive model, or **DirectQuery** only if your organization's PostgreSQL gateway and query-performance policy support it. For the full cohort, start with Import and select only `analytics.business_cohort`.
5. For privacy, use a PostgreSQL account limited to `SELECT` on `analytics.business_cohort`, not the raw schema. Do not save a shared password in a PBIX sent outside the organization.
6. Alternatively, open `business_cohort.m` in Power Query Advanced Editor to see the table query. Apply `business_cohort_types.m` types, then **Close & Apply**.

The query includes each head-office CNPJ basic solely as the unique key. Do not place identifiers in visuals or publish a company-level risk list.

## 2. Model columns and measures

Add the measures from `measures.dax` to the imported table. Use `snapshot_date` for a card and `municipality`, `cnae_division`, `company_size`, `is_mei` as slicers. Do not interpret `is_closed` as economic failure; label it “Administrative baixa observed.” Do not calculate a two-year closure rate from all records: restrict it to companies open at least 730 days before `snapshot_date`.

## 3. Suggested pages

### Page 1 — Regional overview

- Cards: eligible head-office count; registered-capital median (optional); share with known MEI status; snapshot cutoff date.
- Bar chart: company count by municipality.
- Table: municipality, head-office count, baixa observed / head-office count, MEI share (known MEI denominator), median observed age.
- Slicers: municipality, size (ME/EPP), CNAE division, MEI status.

### Page 2 — Survival and sector

- Import the Kaplan–Meier PNG generated by `make analyze` (`output/figures/survival_by_sector.png`). This static figure is calculated in R; do not replace it with an uncensored Power BI proportion. Add the matching snapshot month and event definition next to the visual.
- Add the MEI Kaplan–Meier PNG, and a sector summary table. Do not create an unsupported dynamic filter over a static curve.

### Page 3 — Model and profiles

- Import the real output tables `cox_hazard_ratios.csv`, `logistic_2y_odds_ratios.csv`, and `sector_clusters.csv` as separate tables where those files exist. Show HR/OR and 95% CI alongside the model reference categories/method note from the report.
- Add the k diagnostics and cluster assignment table. Show number of CNAE divisions and mean silhouette. Avoid presenting the cluster as an individual predictor.
- If a model file is absent because a guard skipped estimation, display the corresponding `*_not_estimated.txt` explanation instead of empty/zero values.

## 4. Refresh and source-month integrity

Rerun `make load`, `make analyze`, and `make report` for each chosen archive month. Then refresh Power BI from the same database and re-import CSV result tables if used. Keep all page titles, CSV outputs and report PDF tied to the same `snapshot_date`. Record source month and repository commit in the report footer before sharing.

## 5. Publication caution

The model outcome is an administrative status transition. A baixa may reflect administrative cancellation rather than business failure. The published RFB data are public but remain subject to responsible-use, licensing and privacy obligations. Use aggregated views for broad publication; do not publish an identifiable per-company “failure-risk” table.
